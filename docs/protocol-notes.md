# Дослідницькі нотатки: LoRaWAN та Zigbee

## Архітектура

- **LoRaWAN / LPWAN**: кінцеві пристрої передають uplink до одного чи кількох gateway; gateway передає пакети Network Server, а Application Server обробляє корисні дані. Типова логічна топологія — star-of-stars, не mesh.
- **Zigbee Mesh**: Coordinator формує мережу; Router пересилає пакети й може бути батьківським вузлом; End Device може спати та спілкується через parent. Альтернативні маршрути підвищують стійкість, але залежать від живих routers та якості лінків.

## LoRaWAN параметри

- **SF7/SF9/SF12**: більший spreading factor зазвичай дає більший час передачі та кращу чутливість, але меншу швидкість і більший airtime.
- **ADR**: серверна адаптація швидкості/потужності за якістю каналу; у проєкті це спрощене правило на основі SNR, не реалізація LoRaWAN MAC.
- **Class A**: приймальні вікна після кожного uplink; базовий режим для батарейних пристроїв. **Class B** додає beacon-синхронізовані вікна, **Class C** майже постійно слухає канал і споживає більше енергії.
- **EU868 / duty cycle**: у симуляції показано канали 868.1/868.3/868.5 MHz і умовний 1% ліміт для навчального прикладу. Фактичні правила залежать від піддіапазону та застосовних регіональних вимог.
- **OTAA vs ABP**: OTAA передбачає процедуру приєднання та отримання сесійних параметрів; ABP задає сесійні параметри статично. Архів не виконує реальну автентифікацію чи AES-128 шифрування — ці стани лише відображаються як концептуальна модель.

## Zigbee

- **Адресація**: IEEE EUI-64 ідентифікує пристрій; коротка 16-бітна адреса використовується в межах мережі.
- **Beacon**: може допомагати виявленню/синхронізації мережі залежно від режиму; не кожна Zigbee мережа працює з beacon-enabled режимом.
- **Routing**: у реальній Zigbee mesh застосовуються механізми discovery/maintenance стандарту, зокрема алгоритми на основі AODV-подібного пошуку; цей проєкт моделює таблицю маршрутів спрощено.
- **LQI**: індикатор якості прийнятого лінка, зазвичай 0–255; не є прямим виміром відстані.
- **Self-healing**: після відмови Router 2 симулятор змінює parent для router_3 і перераховує маршрути. Це демонстрація логіки, а не точна реалізація Zigbee stack.

## Порівняння та висновок

LoRaWAN краще підходить для рідкісних невеликих повідомлень на великій відстані з автономним живленням. Zigbee доцільний для локальної автоматизації, частішого обміну та мережі, де вузли можуть ретранслювати пакети. Порівняльні значення latency, delivery та battery тут синтетичні, призначені для демонстрації метрик; вони не є бенчмарком реального обладнання.
